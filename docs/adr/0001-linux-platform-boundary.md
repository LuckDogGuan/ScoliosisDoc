# 单一拍摄状态机与 Linux 平台适配

2026-10-01 决定保留原 C、cJSON、LwBTN 和 V3 状态机，把配对、许可、拍摄规则放在应用层，协议传输、队列、持久化放在中间层，GPIO、RKiPC、音频、Wi-Fi、时钟、进程放在平台层。下一块板仍以 Linux 为目标，优先替换平台实现；不增加通用框架、另一套业务状态机或正式运行的 Python 中间层。旧协议入口仅为显式 legacy 兼容，默认只运行 V3。

当前 RKiPC 二进制在 MP4 开录时没有及时产生首关键帧，实测丢失约 1 秒片头。为保留现有厂商程序和相机配置，使用只作用于 RKiPC 的小型进程内适配库，在 mux 初始化成功后请求 IDR，原参数和媒体帧原样转发；不在初始化中等待首帧，因为厂商代码持有存储互斥锁。适配库的 ABI 已按当前板端库核对；升级 RKiPC 或移植板卡时必须重新核对这个平台文件。它比替换整个厂商 SDK 改动小，但 ABI 兼容是明确维护约束。
