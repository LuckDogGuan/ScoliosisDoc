# 单设备筛查 V1 产品方案（已确认）

> 2026-09-28 确认。第 11 节三个问题已按下面的决定冻结。旧的多设备框架和三栏界面不再作为 V1 依据。
>
> 后来的代码已经超过文内这几句：喇叭可以在 0–30 之间由电脑经 hello 下发，样例配置仍是 10；UDP 发现端口 37020 已在两端实现。产品规则（一台电脑、一台当前设备、四页面）仍以本文为准。未注明“现有”的板端协议，对照 [HTTP 协议](上位机与下位机HTTP协议规范.md) 文首和当前源码。

## 确认记录

1. **就一台电脑，先不考虑。** 已配对仪器能否被其他电脑重新配对、如何阻止同网段抢走连接、首次可信凭据怎样交换：本版不设计、不实现。现场只按一台电脑使用。外接按键到货后，再改“进入配对”的触发方式。
2. **包含。** 导出全校排序名单时，各班明细包含后台记录的“导入时间”列。汇总表仍然只放人数。
3. **确认。** 同一份导入 Excel 里，同一学校、同一学号出现多行时，这些行**全部**列为问题行，不导入，也不私自保留其中一行。老师修正后，只重导问题清单里的行。

本轮只改上位机 `ScoliosisFlutter`。下位机程序、板上音量和现行 `/api/v1` 接口不动。UDP 发现与 `/api/v2` 等下位机后续再做。上位机的“刷新设备”在现有 hello 上报上核对连接；失败时列出已完成的检查和下一步，不一直写“等待仪器报到”。

## 1. 范围与页面

一台电脑同一时间只连接、使用一台仪器。可以保留多个**历史配对记录**，但只有一台“当前设备”；切换当前设备先停止旧设备接收拍摄命令，不影响已保存的视频记录。视频始终归属于筛查、学生和 `capture_id`，不依赖当前设备是否仍配对。

```text
设备页 ── 发现／配对／切换当前设备／历史配对／连接诊断
名单页 ── 导出 Excel 模板／导入预览／单人添加／按班查看名单
拍摄页 ── 选学校→年级→班级／排序／顺序或单独模式／拍摄进度
记录页 ── 按班、姓名、学号、日期查询／查看状态／重拍入口／待同步与未归属
```

软件**默认打开设备页**，先核对当前设备是否连接成功。四个页面始终通过左侧导航切换；在其他页面发现缺少设备或名单时，提示并提供跳转入口，不让老师猜下一步。

## 2. 设备页与发现

- 上位机点击“刷新设备”后，用指定局域网网卡发 UDP 发现请求；设备单播回应。当前设备成功报到后显示“可拍摄”。历史已配对设备可以再次选为当前设备，新设备需要显式配对。电脑 IP 变化时不要求老师改板端配置。
- 发现、HTTP 报到、配对、可拍摄是不同状态；刷新失败显示网络和设备诊断入口，不能一直写“等待仪器报到”。只有一台当前设备能收到拍摄命令，其他发现到的设备只用于配对或切换。
- 设备发现消息不能直接授权上传。当前阶段**仪器开机默认进入配对状态**，电脑端选择发现的设备并发起配对；仪器喇叭播报“连接成功”或“连接失败”。外接按键到货后再改进入配对状态的动作。配对成功后仍须校验电脑身份，防止同一局域网的其他电脑诱导上传。多电脑接管和首次凭据交换本版先不考虑，见第 11 节。
- 本版**不提供 VLC 摆放预览的按钮、自动启动或自动关闭**。用户将来可以独立手动触发推流并启动 VLC。当前 `rkipc` 的 RTSP 服务是否真正关闭，是板端能力问题，不能因为删掉 UI 就声称已关闭；推流开关单独延期验证。

## 3. 名单页与数据约束

- 提供 `.xlsx` 模板导出和 `.xlsx` 导入；保留现有 CSV 导入作为兼容入口，不在主界面强调。Excel 的六个业务列为 `学校、年级、班级、学号、姓名、性别`，**全部必填**。`导入时间`由电脑后台生成和保存，在名单页展示，不要求填入 Excel。模板另设“填写说明”工作表，数据表不放示例学生以免误导入。
- 单人添加与 Excel 导入使用同一套业务字段和校验。学号始终作为文本保存，保留前导零；**同一学校内学号唯一，跨年级和班级也不能重复**，不同学校可以使用相同学号。现有“学校＋年级＋班级＋学号”的判重规则不能直接沿用。姓名可以重名；内部稳定学生 ID 不随学号修改。
- V1 新增学生须填写班级；旧名单若班级为空，导入预览中列为“未分班”，须补齐后才能进入按班拍摄。
- 导入先做一次预检：列出学校、年级、班级、人数、缺失字段、非法性别、同校文件内部重复学号以及与现有名单冲突的学号和行号。发现问题时显示原记录与新记录差异，进入二次核对；**只有用户核对并确认后才导入有效行，问题行不入库，也不覆盖原记录**。完成后分别报告已导入和未导入的行数、行号及原因，并提供**只含问题行**的错误清单供修正后再次导入；不能要求老师重导整份原文件，否则先前导入的有效行会变成新冲突。文件内同一学校、同一学号的多行全部列为问题行，不保留其中任意一行。导入预览按学校列出不同名称，便于发现学校名称误写成两所学校。
- **六个业务字段必填。性别只接受标准输入“男”或“女”**，不接受空值或 `M/F`；旧五列名单须补齐性别及缺失的班级后才能用于本版拍摄。后台生成的导入时间不是用户填写字段：每次确认导入形成一个批次及批次时间，成功导入的各行显示该批次时间，问题行不生成已导入记录；单人添加显示后台记录的添加时间。名单修改时保留原导入／添加时间。
- 学生应有内部稳定 ID；学号、姓名、性别或排序改变，不改变已有视频的归属。已拍摄学生的学校／年级／班级／学号修改需要显式核对，避免把历史记录挂错。

- 最小工作单位是一个班：必须先选学校、年级、班级；排序只作用于当前班。切换排序只改变展示和顺序模式的后续路线，不重写学生 ID 或视频归属。**拍摄页没有导出按钮。**
- 拍摄页重启后恢复上次的学校、班级、模式和选中学生。拍摄中不能切换班级或排序；非拍摄时改排序，要保留当前选中的学生，并清楚预览新的名单次序。
- 主排序为导入顺序、**学号默认升序**、**姓名按拼音排序**；性别分组独立选择不分组、男先、女先，组内沿用主排序。学号保留文本原值和前导零；若以后允许字母等非纯数字学号，比较规则须先核对，不能直接把学号转成数字覆盖原值。
- **顺序模式：** 从本班排序后的待拍名单选中一人，开始后锁定学生；显示录制与上传结果。成功保存到电脑后老师点“下一位”。若上传失败，仍显示“视频留在仪器”，由老师明确选择“待同步并下一位”或重试；程序不在开始时自动跳人。已完成的人可从其记录明确发起重拍。
- **单独模式：** 在**全部学校、全部学生**中搜索姓名或学号，结果同时显示学校、年级、班级、学号、性别和状态，以区分重名；明确选中某一人再拍。拍完停留在该人，不自动跳转。当前班级筛选不限制单独搜索范围。
- 两种模式共用同一个拍摄入口与学生绑定规则。录制中不因暂停心跳而误显示“设备离线”；一台设备同一时间只执行一个拍摄任务。
- 本版不做 PDF。名单排序预览和名单 Excel 导出在名单页；拍摄记录的数据导出归记录页，范围待用户确认后再做。

## 5. 记录页

记录页存每次拍摄的独立记录：学生内部 ID、`capture_id`、设备号、开始时间、文件状态和文件路径。一个学生重拍时保留旧记录，默认标出最新一次；可查看记录信息和文件状态，逐级按**学校→年级→班级**筛选，暂时**不提供视频播放**。待同步、上传失败和未归属视频在这里集中处理，不与普通名单混在一起。删除当前设备配对或重排班级名单，不删除记录。

## 6. V1 明确删减／延期

| 从当前设计移出 V1 | 处理 |
| --- | --- |
| 同时连接多台仪器、多机分配学生 | 不提供；只允许一台当前设备 |
| 拍摄开始即自动切下一人、“停在当前”全局开关 | 删除；顺序模式由老师点“下一位”，单独模式保持所选人 |
| 主页面设备卡片和其中的“解除配对／拍摄”按钮 | 拆至设备页与拍摄页 |
| VLC 摆放预览 UI、自动控制 VLC 或 RTSP | 本版不提供；板端真正启停推流需另做验证 |
| 外接按键和灯的成品 UI | 硬件到货、实测后再加入；设备页仍如实显示电池“未安装” |

现有 10 秒本地录像、上传确认后才删除板端文件、失败留片、开机补传，以及未归属视频的保底保存，属于数据可靠性能力，继续保留。

## 9. V1 拟定通信契约（尚未实现，等待问题确认后冻结）

建议在现有 `/api/v1/*` 旁新增 `/api/v2/*`，实板联调稳定后再切换；本轮不修改现行接口。电脑负责学生和筛查数据，仪器只知道设备号、命令号、拍摄号及媒体文件。

### 9.1 UDP 发现与设备绑定

```text
电脑在选定的局域网网卡广播 DISCOVER {version:2, nonce, http_port}
仪器向请求来源单播 HERE {version:2, nonce, device_id}
电脑对已登记设备发 CONNECT（必须验证双方配对凭据）
仪器校验成功后，临时使用 CONNECT 来源 IP 与 http_port，向电脑发 hello
电脑只把已认证且被选为“当前设备”的那一台标记为可拍摄
```

随机 `nonce` 用于区分本次刷新与旧回复。UDP 回复只是“被发现”，**不能直接授权配对、切换当前设备或上传视频**。当前仪器开机默认进入配对状态，后续按键到货再改触发动作。多电脑重新配对和首次凭据交换本版先不考虑，见第 11 节。配对结果由仪器喇叭播报“连接成功／连接失败”，但语音不能代替电脑端的认证结果和状态显示；不能把任何收到广播的电脑自动写成上传目标。刷新超时应区分“无 UDP 回复”和“收到回复但 HTTP 报到失败”；只有连上 USB 后才有证据判断业务程序是否缺失。

建议的配对状态流（方案，未实现）：仪器开机进入配对状态 → 电脑端选择设备并发起配对 → 双方完成身份核对并持久保存配对信息 → 仪器播报成功或失败 → 电脑端显示结果。超时、取消、认证失败均需显示具体原因；已配对设备的重新配对边界待确认。后续切换历史设备不应重新配对，但仍需验证已保存的凭据。语音文件和板端音频播放在真实设备上单独核对。

### 9.2 HTTP 请求与响应

下表是**待实现的拟定契约**。所有请求带协议版本、设备身份和请求 ID；认证签名的具体格式随首次配对方式确定。HTTP 仍由电脑监听，板端不新开接收视频的 HTTP 服务。

| 拟定接口 | 板端请求 | 电脑成功响应和持久状态 |
| --- | --- | --- |
| `POST /api/v2/hello` | `device_id`、本机 IP、RSSI、剩余空间、摄像头、`battery:{present,percent}`、设备状态；未装电池时 `percent:null` | `200 {"ok":true,"active":true/false}`；只有经过认证且为当前设备时 `active=true`。录制期间不把暂停心跳误判离线 |
| `GET /api/v2/commands/next` | 当前设备 ID 与认证信息 | `200 {"command":"none"}`，或 `{ "command":"capture", "command_id":"..." }`；同一命令在 `start` 确认前可重复返回，不能“读取即删除” |
| `POST /api/v2/captures/start` | `device_id`、`command_id`、板端生成的 `capture_id` | 校验当前设备、命令及电脑内部锁定的学生；成功返回 `200 {"ok":true,"capture_id":"..."}` 并持久化绑定。重复提交同一组合仍返回同一结果；不移动名单游标 |
| `POST /api/v2/captures/status` | `capture_id`、`command_id`、`recorded_local / uploading / pending_local / failed` 之一及可选错误码 | 更新拍摄状态；网络中断时不能假定板端状态，电脑显示“待确认”。录制中进度按开始时间估算，文件结果以实际回执为准 |
| `POST /api/v2/captures/{capture_id}/file` | MP4 二进制正文；认证信息、`command_id`、`Content-Length`、文件 SHA-256；不发送学生个人信息 | 校验命令、长度、哈希和 MP4 基本结构；先持久写入临时文件、再更新记录。仅完成后返回 `200 {"ok":true,"stored":true,"capture_id":"...","sha256":"..."}` |
| `GET /api/v2/captures/{capture_id}/receipt` | 超时或回包丢失时，板端携认证信息只读查询 | 已存且哈希相同返回收件回执；未存返回 `404`。板端按此决定是否重新传，不盲目删本地 MP4 |

电脑点击“开始拍摄”时，先在本地持久建立 `command_id → screening_id + student_id + active_device_id`；设备取得命令后必须带 `command_id` 请求 `start`。电脑只在验证成功后绑定板端 `capture_id`，并保持所选学生不自动前进。板端不接收姓名、学号、性别或班级。

```text
电脑命令已创建 → 设备已接单 → 已确认开始 → 板端录制完成 → 上传中
                                      ├─ 电脑持久保存并回执 → 已完成
                                      └─ 上传失败／回执不明 → 板端留片、电脑待确认
```

**幂等与错误：** `command_id` 和 `capture_id` 必须唯一；重复 `start` 不得二次录像，同一 `capture_id` 的相同哈希重复上传返回同一回执，哈希不同返回冲突。建议 `400` 表示格式错误、`401/403` 表示身份或当前设备不符、`404` 表示命令／回执不存在、`409` 表示 ID 冲突或状态不允许、`413` 表示文件过大、`5xx` 表示电脑未能持久保存。板端**只在已确认持久保存且回执匹配时**删除本地 MP4；超时、断线、非成功状态都保留并可查询回执后补传。错误体应有稳定 `error_code`，界面再翻译成老师能读懂的话，不解析日志字符串。
