## 使用步骤

1. 未配对仪器启动后不响应普通扫描。中键长按 3 秒开放 60 秒配对窗口，电脑刷新后连接；新配对成功自动进入拍摄页，拍摄许可仍关闭。已保存配对允许原电脑恢复，包括地址变化后的身份和事务核对。
2. 顺序模式：选择班级和排序，点击名单查看学生，再点“从此位置开始拍摄”。开始时固定本轮顺序；左右键同时长按 1.5 秒开始，松开任一键停止。正常完成后自动显示和准备下一位；成功待传也参与跳过。明确指定起点允许重拍，旧记录保留。
3. 单独模式：搜索、点击学生查看，再点“拍摄此学生”，实体左右键开录。完成后仍对应此学生；换人需再次明确点击开始。等待按键时可换起点，旧许可和准备 ID 先撤销；录制和收尾时可以浏览但不能替换任务。名单点击不改变视频归属。
4. 左侧导航底部“自动播报下一位姓名”所有页面可调节并保存；关闭立即停止电脑叫号。拍摄页“电脑试听姓名”和设备页“测试喇叭”分别播放电脑姓名与仪器固定测试句。
5. 仪器音量在设备页调整。许可关闭且无录像、收尾、音频任务时可试听；试听临时应用滑块值，结束恢复已保存值，取消不保存。确认保存需板端应用、持久写入和结果确认均完成。失败在弹窗显示可理解提示，原异常和堆栈写入日志。
6. 设备页始终显示当前仪器、历史设备、扫描到的设备三个框，列表为空有空态，沿用去重规则。已配对在线默认自动上传；可暂停或继续。暂停完成已授权文件及回执，不继续授权下一文件；换页保持暂停，重连或应用重启自动恢复。
7. 中键长按 3 秒解除已配对仪器，不断开 Wi-Fi、不删视频。录制中解除会立即撤销旧电脑控制、关闭下一轮许可、请求停录，原 ID 的文件和结果持久化后完成解除。必须松开中键后再次长按才能重新开放窗口；不再使用中＋左、中＋右组合。

短片进入记录并标记需重拍；未知来源视频进入“未归属”，两者均不推进名单。查询回执失败时保留板端文件并退避重试；仅完整保存并通过大小、SHA-256 校验的明确单文件回执允许板端删除。重复接收不重复创建记录。

## 约 1 秒片头缺失的定位

先建立逐帧 PTS、全文件解码与报告时长比较的用例，内含约 1 秒缺失必失败的反例。禁用 IDR 请求时真实板端复现：约 2488 ms 的报告只有约 1533 ms 媒体，首关键帧在约 972 ms。mux 在首关键帧前丢弃不可独立解码帧，导致片头缺失。

在当前板端 ABI 核对后，mux 初始化成功即调用 `RK_MPI_VENC_RequestIDR(0, 0)`。首次尝试第二参数为 1 时返回 `RK_ERR_VENC_NOT_SUPPORT`，该失败记录保留；随后按实际库支持参数修正，关键帧在初始化后 1–51 ms 到达。没有改短报告时长或增加固定等待。最终 21 段全量解码、记录 SHA-256 与原 ID 均匹配，逐帧媒体时间与报告时间最大差 32 ms，小于 100 ms / 3 帧验收界限。`timing-no-idr.json` 与 `timing-final-20.json` 分别保存失败和通过结果。

RKiPC 元数据 `r_frame_rate` 显示 60，但实际 PTS 步长约 1/30 s；测试使用解码帧 PTS，不把这个标称值当实际帧率。平台保留该板原生 60/2 设置。相关厂商接口依据：[VENC 声明](https://raw.githubusercontent.com/LuckfoxTECH/luckfox-pico/main/media/rockit/rockit/mpi/sdk/include/rk_mpi_venc.h)、[RKiPC 存储实现](https://raw.githubusercontent.com/LuckfoxTECH/luckfox-pico/main/project/app/rkipc/rkipc/common/storage/storage.c)，运行证据以当前板端库和录像为准。


代理 Ctrl+C 退出时用保存的配对身份和事务恢复直接 HTTP 端口，并记录结果；随后清除 `INSTRUMENT_DEBUG_PROXY` 并重新启动 Flutter。异常退出时执行相同恢复动作需重新正常启动并退出代理，或重新启动正式 Flutter 恢复连接。代理只接受本机调试 UDP 转发，原 UDP 数据包及校验不变，HTTP 视频以 64 KiB 分块转发，不整段载入内存。普通界面不显示这些细节。

Flutter 协议日志：数据目录 `日志/protocol.jsonl`；异常日志沿用 `ErrorLog`，写入 Flutter 工作目录 `data/logs/error.log`。板端：`/opt/instrument/state/runtime.jsonl`、`mux.jsonl`。Python 为 `--log` 指定文件。日志记录方向、单调时间、UTC、来源端点及相关设备/启动/许可/视频/事件/授权 ID、结果和异常；视频仅记录大小与哈希。各日志 4 MiB 轮转，保留两份旧日志。两端时钟可能未同步，时延使用同侧单调时间并按 ID 关联，UTC 用于辅助核对。音量弹窗回归测试故意产生的拒绝/保存失败会写入异常日志，验收中应与真实硬件错误区分。
