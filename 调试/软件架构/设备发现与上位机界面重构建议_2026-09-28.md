# 设备发现与上位机界面重构建议

> **【已取代】** 多机和三栏界面不要再实现。UDP 后来做成了端口 37020 的 `DISCOVER` / `here`，没有做本文后面的 CONNECT 凭据。四页面、15 秒在线、开录不自动切人，见 [架构说明](说明.md)。

> 2026-09-28 用户已将 V1 收敛为一对一设备与四个独立页面；本文件里的多机和三栏界面草案已由[单设备 V1 方案](单设备筛查V1产品方案_待确认.md)取代。UDP 发现思路仍可参考。

> 2026-09-28 现场复核；这是待确认的产品方案，尚未修改 Flutter 或 C 的发现协议与界面。

## 已确认的问题

1. 当前下位机只向配置里的固定 `pc_base_url=http://192.168.0.20:8080` 主动 `hello`。电脑换 IP、业务程序未运行或局域网隔离时，上位机只能显示“等待仪器报到”，没有主动发现与可操作的故障信息。广播不能修复未运行的程序或被隔离的网络。
2. 2026-09-28 实板检查发现业务二进制曾只放 `/tmp`，重启后已消失。现已重新部署到 `/userdata/instrument/instrument_app`，用 `/oem/usr/etc/init.d/S80instrument` 开机启动；一次重启后程序、Wi-Fi 和上位机设备卡片均恢复。
3. 当前 Flutter `DeviceInfo.online` 只看最近 10 秒 `hello`；业务录像期间同步录 10 秒且暂停报到，因此正常拍摄可能被界面误标成“未连接”。排队命令被设备取走即清除，界面没有“已接单／录制中／上传中”的确认链。
4. 当前视频列表只按“当前学生”过滤，而 `capture/start` 成功后立即前进到下一人；最后一位拍完后当前学生为空，刚上传的视频不再出现在主列表。现有“停在当前（重拍）”是隐含模式，容易把下一次拍摄挂错人。
5. 当前页面的设备、当前学生、视频分为纵向三段；设备卡片占左上小块，大片留白，主要拍摄动作在卡片内部；“解除配对”和“拍摄”相邻。空界面没有清楚的下一步，Debug 标记和技术状态文字不应出现在正式交付版。

## 建议的连接方式

电脑端保留现有 HTTP 接收与上传协议，新增局域网 UDP 主动发现。上位机点击“刷新设备”后，对选中的网卡广播带随机 nonce 和协议版本的发现请求；下位机常驻监听，向请求源地址单播回复设备号、协议版本和 nonce。电脑识别已登记的仪器后，再向它单播带配对凭据校验的连接指令；仪器验证后向这个电脑地址发 `hello`。上位机显示“发现设备 → 报到成功 → 已配对／待配对 → 可拍摄”的分段结果。成功回连后按设备号维持心跳与持久配对，电脑 IP 改变时不需改板端固定地址。扫描每轮约 2–3 秒，自动在启动、电脑网络变更和板端重连时触发；“刷新设备”随时可手动触发。

```text
电脑 [刷新设备]
  ├─ 选择当前专用网卡，广播 DISCOVER(version, nonce, 电脑端口)
  ├─ 仪器单播 HERE(device_id, nonce, version)
  ├─ 电脑单播经配对凭据验证的 CONNECT；仪器只信任验证通过的电脑
  ├─ 仪器向 CONNECT 来源 IP:端口发 hello，电脑记录实际连接结果
  └─ UI：已发现 / 报到失败 / 待配对 / 可拍摄（分别显示）

拍摄命令仍由既有 HTTP 接口交付；UDP 只负责发现，不承载视频和学生数据。
```

**约束：** 首版应先在专用路由器的同一局域网验证，电脑接网线、仪器接 2.4 GHz Wi-Fi，关闭客户端隔离；广播不会穿越一般路由器或被隔离的无线客户端。多网卡时必须明确选择专用网卡，不能只猜 `WLAN`。设备回复不可直接作为配对或上传目标的授权。每台仪器的配对凭据可在首次 USB 维护时配置到电脑和板端；后续 `CONNECT` 必须带随机挑战和校验码，HTTP 报到与上传也要验证设备身份，避免同网段其他电脑诱导上传视频。正式部署还需确认视频传输的加密要求。若发现失败，保留“高级设置中的手动地址／USB 诊断”作为维护入口。

广播主要解决动态地址与可恢复性；当前每秒取命令的拍摄响应本身最多约 1 秒，是否要改成长轮询，应等现场测量后决定。

## 拍摄状态与学生归属

以 `capture_id` 为一次拍摄的唯一状态源：`待下发 → 仪器已接单 → 录制中 → 待上传／上传中 → 已保存到电脑／留在仪器／失败`。录像中暂缓心跳时仍显示“录制中”，不凭 10 秒未报到直接判离线。上位机收到开始确认时原子锁定学生；可以提前显示下一位待拍以支持多机连续拍摄，但“正在拍摄／最近完成”固定显示刚才那个人，上传结果不会因名单前进而消失。重拍从该学生的记录中直接发起，界面明确显示“为某某重拍”，不使用全局“停在当前”开关。

## 建议验收

- 电脑 IP 变化、先开板后开电脑、先开电脑后开板：点一次“刷新设备”均可恢复，无需修改板端配置。
- 下位机重启后程序自动运行并报到；无 UDP 回应时界面明确列出网络隔离、设备未启动等可能原因。只有 USB 诊断连到板端后，才能进一步确认“业务程序缺失／未运行”。
- 同网段两台设备能区分“发现、配对、在线、拍摄、上传、离线”，多机同时开始时不会把同一学生分给两台。
- 最后一位拍完，最近视频和结果仍可见；重拍必须显式指定学生；上传失败保留板端文件并可重新处理。
- 断网、客户端隔离、防火墙阻断、HTTP 服务未启动时显示不同的排查提示；扫描不得静默覆盖既有配对或视频归属。
