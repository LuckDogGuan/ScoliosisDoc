| 声音类型 | 播报内容 | 发声设备 | 声音来源 / 机制 | 板端资源开销 |
| :--- | :--- | :---: | :--- | :---: |

## 二、电脑端（上位机）语音播报系统详细设计

### 1. 播报时机与文本生成
* **触发时机**：
  * 老师在电脑端点击【下一位】切换待检学生时；
  * 录像上传完成且上位机保存成功后，系统自动推进到下一位学生时。
* **播报文案**：`"下一位，" + student.name`（例如：`"下一位，王浩然"`、`"下一位，李欣怡"`）。
* **离线合成方案**：
  * 调用 Windows 原生离线语音引擎（`SAPI.SpVoice` 或 WinRT SpeechSynthesizer，音色选用中文离线包，如 `Microsoft Huihui`）。
  * 单句合成仅需约 50ms，直接向系统音频输出管道发声，**不依赖外网、无需任何云端 API**。

### 2. 播报开关与测试按钮（UI/UX 规范）

在【拍摄页】上方控制栏和当前学生卡片中集成以下控制组件：

```text
┌───────────────────────────────────────────────────────────────────────────────────────┐
│ 拍摄                                                          当前设备：CAM-000123 ●  │
│ 第一小学 → 五年级 → 1班                                                              │
│ [顺序模式 ●] [单独模式]        [√] 自动播报下一位姓名                                 │
├───────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                       │
│  本班第 8 / 35 位                                                                     │
│  学号：1010108       姓名：王浩然       性别：男                                       │
│                                                                                       │
│             [开始拍摄 (10秒)]          [🔊 测试播报当前姓名]                          │
│                                                                                       │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

#### 2.1 【开关】自动播报下一位姓名
* **位置**：拍摄页顶部模式切换栏右侧。
* **控件形态**：复选框或 Switch 开关，文字标注为 **`自动播报下一位姓名`**。
* **默认状态**：默认打勾开启（Checked）。
* **配置持久化**：状态保存在本地配置中（下次打开软件自动恢复上次的选择）。
* **运行逻辑**：
  * **开启状态**：录像上传成功自动切人、或老师手动点击界面“下一位”时，电脑扬声器立即发声叫号：“下一位，xxx”。
  * **关闭状态**：切人时电脑完全静默，界面仅更新学生卡片。

#### 2.2 【按钮】测试播报当前姓名
* **位置**：紧随【开始拍摄】按钮右侧，采用辅助按钮（OutlinedButton）样式：**`[🔊 测试播报]`**。
* **功能**：点击后，电脑扬声器立即朗读当前正在高亮显示的学生姓名：“下一位，[当前姓名]”。
* **设计目的**：在开考或开检前，老师可随时点击测试电脑扬声器音量大小、发音清晰度，无需先录制一段视频。

## 三、取消拍摄设备强连接限制的设计

### 1. 现状痛点
现有逻辑在点击【开始拍摄】时进行了以下强校验：
```dart
if (devices.currentId == null || !devices.paired.contains(devices.currentId)) {
  return '请先在设备页配对当前设备';
}
if (!devices.currentReady) return '当前设备不在线，请先刷新设备';
```
导致在没有物理仪器、脱机备课、教师演练或纯粹核对名单及离线语音时，无法推进流程。

### 2. 改进方案（支持脱机模拟与实机拍摄双模式）
* **当有配对设备且在线时**：正常向板端下发拍摄命令（`queueCapture`），驱动真实仪器拍摄并上传视频。
* **当无配对设备或设备离线时**：
  * 不阻断用户点击【开始拍摄】；
  * 自动进入 **本地模拟拍摄（Mock Capture）**：
    1. 按钮点击后进入 10 秒倒计时录制阶段（UI 显示 `录制 01/10 秒`）；
    2. 10 秒倒计时结束，模拟进入 `已保存到电脑` 状态；
    3. 老师点击【下一位】或自动推进，电脑触发语音播报：“下一位，李欣怡”；
    4. 生成一条带有 `MOCK_OFFLINE` 标记的本地空跑测试记录。
* **收益**：即便没有硬件板子在手，老师或研发也能直接完整演练整个筛查翻页与语音叫号闭环。
