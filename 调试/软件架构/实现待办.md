## 暂停执行、待核对

- 用户已同意先按多机学生唯一处理：收到 `capture/start` 时串行锁定并前进；“停在当前”用于显式重拍，同一学生正在拍摄时第二台返回冲突。设计第 4.3、8.4 节已统一该时序。
- Cursor 规划中的 `ffmpeg` 拉本机 RTSP 再封装备选路径尚未证实符合“录制 10 秒不推流、只保留一个编码进程”的要求，暂不执行。
- 设备发现仍依赖板端配置中的固定 `pc_base_url` 和板端主动 hello。若电脑 IP 改变、业务进程未启动或网络隔离，Flutter 仅显示“等待仪器报到”，没有发现、重试和故障定位入口；需要重新设计发现协议与界面状态。
- Cursor 规划中的 BusyBox `wget --post-file` 视频上传在实板测试中出现 HTTP 200 但电脑收到 0 字节，已停用；C 直接上传已完成一次完整实板链路，另一次直接传原片的电脑/板端 SHA256 一致；连续性仍待测。
- `rkipc` 原生录制可用，但录制期间 RTSP 仍可被客户端拉取；现有 socket 没有独立暂停 RTSP 的已确认接口。不冒险重启编码器，自动停推流留待后续核对。
- Windows 8080 直连已成功，当前两个 `scoliosis_flutter` 入站规则读到 Allow；原先 Block 状态已变化，具体修改者未追溯。测试热点的偶发路由超时仍存在，不把一次成功视为稳定性结论。
- 外接按键、灯、主电池、专用路由器尚未到手，GPIO、灯电路和低电功能保持待硬件。
