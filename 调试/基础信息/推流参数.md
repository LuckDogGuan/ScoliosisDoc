# 推流参数

只在这里改当前要用的数字。画质优先的这一档见下面的表。过程在 `../记录/Pico_Zero_WiFi推流压参_2026-09-27.md` 和 `../记录/Pico_Zero_推流30帧定位_2026-09-27.md`。

256 kb/s、30 fps 时，1080p 每帧大约只有 1 KB，画面一动就会糊，而且看一会儿后网关 ping 会失败，VLC 就报连不上。现在改为 15 fps、512 kb/s：总流量仍低，每帧大约 4 KB。40 秒 Wi-Fi 拉流期间网关 ping 保持全通。

输出帧率用分数。不要改成 `15/1` 或 `30/1`，整数路径不会按传感器的 60 fps 丢帧。

| 键 | 当前值 | 作用 |
| --- | --- | --- |
| `isp.0.adjustment:fps` | 60 | 传感器实际帧率 |
| `video.0:src_frame_rate` | 60/1 | 与传感器一致 |
| `video.0:dst_frame_rate` | 60/4 | 编码器输出 15 fps |
| `video.0:width` / `height` | 1280 / 1080 | |
| `video.0:output_data_type` | H.265 | |
| `video.0:rc_mode` | CBR | |
| `video.0:max_rate` | 512 | 单位 kb/s |
| `video.0:gop` | 15 | 15 fps 下约 1 秒一个 I 帧 |
| `video.0:stream_smooth` | 100 | 减少码率突发 |
| `video.0:enable_motion_deblur` | 0 | |

板上 `/userdata/rkipc.ini` 已是这套。Wi-Fi 省电需关闭，重启后要再执行：

```sh
iw dev wlan0 set power_save off
```

预览（RTSP over TCP，网络缓存 1000 ms）：

```text
rtsp://192.168.0.66:554/live/0
```

USB 转发不走这张容易堵住的网卡：

```text
adb -s 3253c006806f5194 forward tcp:8554 tcp:554
rtsp://127.0.0.1:8554/live/0
```

内核日志应出现 `fps fix [60/1] -> fix [60/4]` 和 `bps [480000:512000:544000]`。
