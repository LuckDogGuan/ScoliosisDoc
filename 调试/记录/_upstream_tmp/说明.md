# `_upstream_tmp` 是什么

这是 2026-09-27 打通「原生录 10 秒」时留下的参考材料，跟 [10 秒录像通路](../Pico_Zero_10秒录像通路_2026-09-27.md) 放在同一层，因为那篇记录写的是「同目录」。不要把它当成下位机工程，也不要拿到 WSL 里编译。

下位机业务程序在 WSL `Luckfox-Ubuntu-22.04:/home/guanjx/luckfox/Scoliosis`，入口是 `src/app/app_controller.c`，目标名 `instrument_app`。它自己实现了一个很小的客户端，去连板上已经在跑的 `rkipc`。本目录里的 `.c` 是 `rkipc` 那一侧的上游摘录，用来看 `/var/tmp/rkipc` 这个 UNIX socket 怎么收命令、录像怎么封进 MP4。

## 上游摘录（解释 rkipc，不是本仓库要编的程序）

| 文件 | 对应什么 |
| --- | --- |
| `socket_server_server.c`、`socket_server_socket.c`、`socket_server_socket.h` | rkipc 的 socket 服务。监听路径是 `/var/tmp/rkipc` |
| `storage_storage.c` | rkipc 的存储/封装。`rk_storage_record_start` / `rk_storage_record_stop` 在这里 |
| `rv1106_main.c` | rkipc 自己的主程序（读 `/userdata/rkipc.ini`）。业务主程序不是这个文件 |
| `rkipc_video.c.upstream` | 同一套 rkipc 的 `video.c`，原先放在 Luckfox 仓库根目录，归到这里和其它上游摘录放在一起 |

## 当时在板子 `/tmp` 上跑的探针（一次性）

| 文件 | 做什么 |
| --- | --- |
| `rkipc_call.py` | 连 `/var/tmp/rkipc` 的最小客户端。`capture_probe.py` 和 `rtsp_during_capture_probe.py` 用 `from rkipc_call import call`，三个文件必须留在同一目录 |
| `capture_probe.py` | 把帧率、码率、GOP 改成正式录像参数，录约 10 秒，再改回预览参数 |
| `rtsp_during_capture_probe.py` | 录像过程中用 ffmpeg 拉本机 RTSP，看录的时候预览还在不在 |
| `t1.sh`、`t2.sh` | 板上计时用的 shell，调用 `/tmp/rkipc_call.py` |
| `proxy_18080.js` | 电脑上的临时代理：`192.168.0.20:18080` 转到本机 `8080`。用来试当时的上传，不是产品路径 |
| `instrument_config_proxy.json` | 配合那个代理的配置快照，`pc_base_url` 指向 `18080` |
| `hello_probe.json` | 一次早期 hello 正文。字段比现在的 hello 少 |
| `instrument_app_current` | 当时从板子拉回来的 `instrument_app` 可执行文件（约 47 KB）。对照用，不是 WSL 里现在这份源码编出来的程序 |

产品里的录像参数在下位机 `config.example.json` 和 `src/capture/`，预览推流档在 `调试/配置/方案/`。两套数字不要混用。
