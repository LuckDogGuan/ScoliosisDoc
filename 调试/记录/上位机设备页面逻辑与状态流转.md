## 一、 页面核心结构总览

设备页面（`DevicePage`）纵向由 3~4 个核心区域构成：

```
+-------------------------------------------------------------------------------+
|  设备                                                    [ (图标) 刷新设备 ]  |  <- 顶部标题与操作
+-------------------------------------------------------------------------------+
|  [!] 提示栏 (仅在设备服务未启动 / 8080端口冲突等异常时显示)                   |
+-------------------------------------------------------------------------------+
|  +-------------------------------------------------------------------------+  |
|  | [当前连接] [状态药丸: 在线可拍摄 / 已配对... / 已发现未配对 / 未配对]   |  |  <- 1. 当前连接卡片
|  | 设备ID (如 CAM-000123 / 等待选择或配对)             [断开并解除配对]    |  |     (_CurrentDevice)
|  | ----------------------------------------------------------------------- |  |
|  | [ 指标芯片组: 信号质量 | 电量 | 存储剩余 | 可用内存 ]                   |  |
|  | 待上传 X 条 · [查看记录]                                                |  |
|  | 固件 / IP / Wi-Fi / 摄像头 / 最近报到 / 连接步骤                       |  |
|  +-------------------------------------------------------------------------+  |
+-------------------------------------------------------------------------------+
|  +-------------------------------------------------------------------------+  |
|  | 新发现 (Badge: 数量)                                                    |  |  <- 2. 新发现卡片

|  +-------------------------------------------------------------------------+  |
+-------------------------------------------------------------------------------+
```

## 二、 五大典型状态与 ASCII 界面呈现

### 状态 1：完全未配对过任何仪器（初次安装 / 干净环境）

#### 1. 数据状态
* `book.currentId == null`
* `book.paired` 为空集合 `{}`
* `book.lastConnected` 为空字典 `{}`
* `book.devices` 为空字典 `{}`
* 侧边栏状态：`未选设备`

#### 2. ASCII 页面展现

## 四、 关键代码逻辑核查与问题说明 (Code Issues & Pitfalls)

基于对实际代码逐行审查，当前上位机代码存在 **3 处明显的交互逻辑缺陷与 Bug**，需要特别说明：

### ⚠️ 问题 1：【交互死锁】“已发现 未配对” 状态下卡片缺乏配对操作入口
* **代码依据**：[`device_page.dart:181-209`](file:///D:/code/Scoliosis/ScoliosisFlutter/lib/ui/pages/device_page.dart#L181-L209)
  ```dart
  if (paired) ...[
    OutlinedButton.icon(
      label: const Text('断开并解除配对'),
      onPressed: () => ...,
    ),
  ]
  ```
* **问题现象**：
  在用户截图所处的这种场景（`currentId` 存在但 `!paired`）下：
  1. `_CurrentDevice` 仅在 `paired == true` 时才渲染右侧按钮，**导致界面上没有提供任何 `[配对仪器]` 按钮**。
  2. `_Discovered`（新发现列表）会通过 `!controller.devices.lastConnected.containsKey(device.id)` 过滤，因为该仪器以前连过，所以不会出现在新发现列表中。
  3. `_History`（历史设备）会通过 `.where((id) => id != book.currentId)` 过滤，把当前选中的 `currentId` 排除了。
  4. **最终结果**：该仪器在当前卡片没配对按钮、在新发现被过滤、在历史设备被过滤，用户在页面上**陷入死锁，无法从 UI 上发起配对**！
* **解决建议**：
  在 `_CurrentDevice` 中增加 `else` 分支，当 `!paired && device != null` 时，显示 `[配对该仪器]` 按钮，点击调用 `controller.pair(device.id)`。

---

### ⚠️ 问题 2：【读数困惑】为什么副标题有数字，主标题却显示“未上报”？
* **代码依据**：[`device_page.dart:290-340`](file:///D:/code/Scoliosis/ScoliosisFlutter/lib/ui/pages/device_page.dart#L290-L340)
  ```dart
  final fresh = device.lastHello != null &&
      DateTime.now().difference(device.lastHello!).inSeconds < 15;
  
  final storage = percent(device.storageFreeMb, device.storageTotalMb);
  
  _MetricChip(
    label: '存储剩余',
    value: fresh && storage != null ? '$storage%' : '未上报',
    detail: device.storageFreeMb == null ? '—' : '${device.storageFreeMb} MB',
    color: color(storage),
  )
  ```
* **问题现象（即用户截屏中的显示原因）**：
  1. **条件一（时效失效）**：代码规定距离最近一次报到必须在 **15 秒内**（`fresh`），一旦仪器断开或超过 15 秒没收到心跳，`value` 直接变成 `'未上报'`。但是 `detail`（详情）只判断了 `storageFreeMb == null`，所以仍然显示上次缓存的 `205 MB`。
  2. **条件二（总空间缺项）**：计算百分比依赖 `device.storageTotalMb` 和 `device.memoryTotalMb`。如果下位机未上报总量，`storage` 为 null，也会强制显示为 `'未上报'`。
* **解决建议**：
  当处于离线或非 fresh 状态时，应当更合理地展示为 `205 MB (离线缓存)`，或者当没有百分比时直接将大字显示为 `205 MB`，而不是一方面写“未上报”，下方又写“205 MB”，造成用户困惑。

---

### ⚠️ 问题 3：超时时间窗口定义分散且不一致
* **代码依据**：
  - 侧边栏与拍摄允许状态（`DeviceInfo.online`）：阈值为 **10 秒**（`difference < 10`）
  - 指标芯片（`_MetricGrid.fresh`）：阈值为 **15 秒**（`difference < 15`）
  - 主卡片 UDP 活跃判断（`_statusLabel.udpRecent`）：阈值为 **20 秒**（`difference < 20`）
* **问题现象**：
  在网络抖动或心跳间隔（当前下位机心跳为 2~3 秒）异常时，会出现极其矛盾的界面表现：
  - 侧边栏在第 11 秒已经显示为“离线”；
  - 设备主页面药丸在第 11~14 秒可能依然是“正在连接”或指标还在刷新；
  - 第 16 秒指标芯片突然集体变成“未上报”。
* **建议**：
  统一在配置或常量类中收拢心跳超时时间（例如统一为 15 秒判定离线）。

## 五、 总结与操作指南速查表

| 当前界面表现 | 背后真实数据条件 | 用户应如何操作 / 恢复途径 |
|---|---|---|
| **未配对**（空白引导） | `currentId == null`，未曾记录任何设备 | 打开仪器电源，点击右上角 `[刷新设备]` |
| **新发现列表有设备** | 局域网收到 UDP 广播，且该设备从未连接过 | 点击该行的 `[配对并设为当前]` |
| **在线 可拍摄**（绿灯） | 已配对且 10 秒内有心跳 | 可前往「名单/拍摄」页正常开展筛查 |
| **已配对 X秒前**（黄灯） | 已配对但仪器关机/断网超过 10 秒 | 检查仪器 Wi-Fi 连接或重启仪器进程 |
| **已发现 未配对**（截图现象） | 选为当前但不在 `paired` 表中 | **存在交互死锁 Bug**；需要代码补全配对按钮，或重置 `设备.json` |

### 1. Bug 修复逻辑与代码落地方案

#### (1) 交互死锁修复（未配对时在当前卡片提供配对入口）
* **涉及文件**：[`lib/ui/pages/device_page.dart`](file:///D:/code/Scoliosis/ScoliosisFlutter/lib/ui/pages/device_page.dart)（`_CurrentDevice` 类的头部操作区，约 L181~L209）
* **修改逻辑**：
  原代码仅在 `paired == true` 时渲染 `[断开并解除配对]` 按钮；当状态处于“已发现 未配对”时右侧完全留空。
  **修复方案**：增加 `else if (device != null)` 分支，提供直接配对按钮：
  ```dart
  if (paired) ...[
    OutlinedButton.icon(
      onPressed: () => _confirmUnpair(...),
      icon: const Icon(Icons.link_off, size: 16),
      label: const Text('断开并解除配对'),
    ),
  ] else if (device != null) ...[
    FilledButton.icon(
      onPressed: () => controller.pair(device.id),
      icon: const Icon(Icons.link, size: 16),
      label: const Text('配对仪器并启用'),
      style: FilledButton.styleFrom(
        backgroundColor: AppColors.primary,
        padding: const EdgeInsets.symmetric(horizontal: 16, vertical: 8),
      ),
    ),
  ]
  ```

### 3. 喇叭音量调节与持久化全链路方案

#### (1) 下位机代码与硬件机制深度核对
经过逐行审查下位机代码与实板 ALSA 驱动：
* **ALSA 硬件范围**：通过开发板执行 `amixer -c 0 cget name='DAC LINEOUT Volume'` 确认：
  - 控制器：`numid=24, name='DAC LINEOUT Volume'`
  - **有效取值范围为 `0 ~ 30`**（step 1.5dB，0 为静音/最小，30 为硬件最大声）。
* **下位机现有代码缺陷**：
  - 启动阶段：`app_controller.c:353` 执行 `audio_set_volume(config.volume);`。
  - 数据读取：`config.c:43` 通过 `number_field(audio, "volume", &config->volume)` 从 `config.json` 加载。
  - **持久化缺失**：**下位机源码中没有任何写回 `config.json` 的函数（无 `config_save`）**。一旦断电重启，音量只能还原为出厂写在 `config.json` 里的静态数值！

#### (2) 下位机持久化方案（确保开机不重置）
为下位机 [`src/config/config.c`](file:///home/guanjx/luckfox/Scoliosis/src/config/config.c) 增设原子保存函数：
```c
int config_save_volume(const char *path, int volume) {
    if (volume < 0 || volume > 30) return -1;
    FILE *file = fopen(path, "rb");
    if (!file) return -1;
    char text[8192];
    size_t len = fread(text, 1, sizeof(text) - 1, file);
    fclose(file);
    text[len] = 0;
    
    cJSON *root = cJSON_Parse(text);
    if (!root) return -1;
    cJSON *audio = cJSON_GetObjectItemCaseSensitive(root, "audio");
    if (audio) {
        cJSON_ReplaceItemInObject(audio, "volume", cJSON_CreateNumber(volume));
    }
    
    char *new_text = cJSON_Print(root);
    cJSON_Delete(root);
    if (!new_text) return -1;
    
    // 采用原子写入机制，防止断电导致 config.json 损坏变空
    char tmp_path[256];
    snprintf(tmp_path, sizeof(tmp_path), "%s.tmp", path);
    FILE *out = fopen(tmp_path, "wb");
    if (!out) { free(new_text); return -1; }
    fputs(new_text, out);
    fflush(out);
    fsync(fileno(out));
    fclose(out);
    free(new_text);
    
    return rename(tmp_path, path);
}
```
* **效果**：写回成功后，下位机掉电重启再次加载 `config.json`，依然保持设定音量，绝不丢失。

#### (3) 上下位机通信协议扩展
下位机每 2~3 秒就会主动向电脑发送 `/api/v1/hello` 心跳。无需新增复杂端口，采用声明式配置同步：
1. **下位机上报当前音量**：
   在 [`src/net/upload.c`](file:///home/guanjx/luckfox/Scoliosis/src/net/upload.c) 的 `http_hello()` 中，请求体附加 `"volume": config->volume`。
2. **上位机下发目标音量**：

   `"volume": targetVolume`。
3. **下位机自动比对并应用落盘**：
   下位机在收到 hello 应答后：
   ```c
   cJSON *vol_item = cJSON_GetObjectItemCaseSensitive(response, "volume");
   if (cJSON_IsNumber(vol_item)) {
       int target_vol = vol_item->valueint;
       if (target_vol >= 0 && target_vol <= 30 && target_vol != config->volume) {
           audio_set_volume(target_vol);          // 1. 硬件立即生效
           config->volume = target_vol;            // 2. 内存状态更新
           config_save_volume(config_path, target_vol); // 3. 永久持久化落盘
       }
   }
   ```
