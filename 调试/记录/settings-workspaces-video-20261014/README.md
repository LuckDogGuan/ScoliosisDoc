## 行为

1. 设置通过左侧导航进入右侧工作区，不再使用弹窗或选项卡。工作空间、历史目录、播报、视频保存、关于都在一页；宽窗口两栏，窄窗口向下滚动。左侧工作空间进度持续可见。
2. 打开目录规范化当前实际目录，经过存在性检查，通过 Windows `ShellExecuteW` 打开。失败给出提示并记录错误，不忽略调用结果。
3. 历史路径及最近打开时间保存在应用全局 SQLite。启动、创建和打开空间都会记录；重复路径合并，旧 `lastWorkspace` 会带入历史。历史按钮直接切换，仍保护拍摄、待传和接收中的数据；目录不存在或无工作空间标记时拒绝，不重建丢失目录。验证已有目录采用只读连接，不迁移非当前数据库、不重置正在计算的状态。
4. 已把 `D:\code\Scoliosis\工作空间\test202610` 与 `D:\code\Scoliosis\ScoliosisFlutter\build\ui-review-workspace` 加入正常应用配置的历史列表，实际当前 `lastWorkspace` 保持前者。此前测试空间现已包含用户实拍记录，保留原位。迁移前后键值见 `workspace-history-seed.json`；不是跨空间合并名单或记录。
5. “计算完成后保留视频”默认关闭，保存为全局设置。只有新视频成功算出有效读数后才清理其原视频，曲线、记录、时间、大小与 SHA256 留存。失败、缺失读数、正在上传、待分析、历史已完成视频不批量清理。开启后保留新视频；已删除的原视频不能恢复或重新计算。
6. 单文件清理先持久化意图，再核对归属、路径、实际大小和哈希，并检查符号链接解析后仍在工作空间内。上传中的清理延后；重启只恢复已记录的清理意图。清理失败单独记录，不把已完成分析改成失败，不反复清理有错误的文件；结果页提示原视频已清理或清理未完成。
7. 按设置清理后，重复上传凭匹配的持久校验记录正常确认，不重建拍摄记录。没有清理标记而丢失的视频仍报错，不能冒充保存成功。
8. 按用户追加要求，导出按已有数据处理，不因测试数据来源、离线演练设备或算法版本分类而过滤记录、数值或曲线，不显示“历史测试”结果标签。汇总按导出记录去重人数和计次；有效数值继续检查错误/有限值，缺失处断线。原算法版本仍集中列在汇总信息中。软件实时进度和界面判定规则保持现有口径。
