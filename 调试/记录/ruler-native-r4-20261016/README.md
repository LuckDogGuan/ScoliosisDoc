## 行为

沿用 FFmpeg 抽帧，每 5 帧取第 3 帧，保留原帧号、时间戳及 1280×1080 原尺寸 PNG。专用后台 Isolate 加载一次 DLL 和模型并顺序处理图片，WIC 解码后按参考实现相同的整数公式生成灰度。模型参数为版本化原生包，运行时不需要外部 Python、NumPy 或 OpenCV。

单帧拒读保存原时间和原因，角度为空，不计入角度统计，曲线断开，真实 0°仍是有效值。加载、参数、尺寸、解码等系统错误或整段没有有效读数时，任务失败，录像结果显示红点，详情保留；没有弹窗、旧算法自动回退或失败重试入口。程序中断的运行任务恢复为待处理，已失败任务不恢复。取消后丢弃迟到结果，当前 C 调用返回后再释放资源。

旧引擎、旧安装包仍保留用于明确回退；回退前保留业务数据库备份。界面没有新增算法选择。新旧算法结果共用既有数据库、曲线及导出接口，记录显示不再被旧版本号过滤。

## 原理

它先在固定画面中寻找尺子阴影与刻度的关系。右侧能可靠定位时，用定位位置和标定点换算角度；另一分支把局部灰度图归一化，与训练得到的局部参考图比较，再综合邻近参考角度。曝光、位置、参考范围或邻居一致性不合格时拒读。此次将第四轮计算迁移到 C，保留匹配、权重和拒读条件；没有重新训练或只修改旧预览参数。

## 同机效率

CPU：AMD Ryzen 7 H 255，Windows 11。以下是开发机的实测，操作系统文件缓存未控制，不保证其他电脑达到同样数值。

| 环节 | 样本次数 | 中位数 | 95 百分位 | 最大值 |
|---|---:|---:|---:|---:|
| C 模型加载及校验 | 20 | 2.48 ms | 2.72 ms | 2.89 ms |
| Python 热态纯算法 | 186 | 3.32 ms | 4.41 ms | 8.62 ms |
| C 热态纯算法 | 186 | 1.12 ms | 1.51 ms | 1.82 ms |
| PNG 读取及 DLL 单张调用 | 62 | 21.51 ms | 25.65 ms | 30.30 ms |

DLL 模块加载一次约 2.23 ms；C 模型加载不含 Dart 的清单哈希校验。纯算法比较采用同一电脑、同一灰度图、逐张交替调用 Python/C 并重复三轮。数据见 [native-performance-03.json](native-performance-03.json)、[native-model-load.json](native-model-load.json)。先前的 2.71 ms 仅是另一轮 Python 热态纯算法结果，不代表整张 PNG 或录像耗时。

| 正式录像流水线 | 采样位置 / 有效 | 总耗时 |
|---|---:|---:|
| V01 | 75 / 71 | 7.215 s |
| V02 | 75 / 74 | 7.010 s |
| V03 | 67 / 65 | 6.338 s |
| V04 | 57 / 52 | 5.177 s |

上述录像长约 11～15 秒，总耗时包括录像哈希、ffprobe、PNG 抽帧、参数加载、PNG 解码/计算和逐帧入库。同一 V01 的旧流程为 46.162 s，75 个位置均未读出有效角度，见 [旧流程计时](flutter-legacy-pipeline-results.json)。该对比只能说明这段录像的运行耗时改善，不能以无输出的旧流程衡量精度，也不构成所有录像都更快的保证。

四段不同录像合并计时的中位数为 6.674 s，95 百分位 7.185 s，最大 7.215 s；每段仅测一次，样本量小且内容不同，不是同一录像的多轮稳定性基准。
