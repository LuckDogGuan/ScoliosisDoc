# V3 跨端协议审查与验收矩阵

2026-10-01；独立只读审查，依据 10:18 实施计划、9月30日两份说明及两端真实源码。本文不代表实板通过。

## 冻结字段

UDP 37020，JSON 最大 4096 bytes，`version:3`、小写 `op`。共同身份和回声字段为 `device_id/host_id/boot_id/sequence/nonce`；发现及 hello 只读、不续许可、不修改配对目标。变更控制单通道递增序号，停止优先。

许可 `gate_id/ttl_ms`，默认 6000 ms，2 秒续期；失效后 `capture_renew` 不得重新开启。上传许可为单个 `capture_id/grant_id`，最长 30000 ms，文件 POST 携带 `Grant-ID`。

完成 HTTP `/api/v1/capture/status`：`version:3, phase:completed, device_id, capture_id, event_id, gate_id, result:success|short|failed, duration_ms, started_at_ms, ended_at_ms, stop_reason`；recording 带实际 `started_at_ms`。

## 关键初始差异

- 原 Flutter `capture/start` 才分配学生，V3 要先持久映射后 prepare，start 只消费映射。
- 原 C `discover_poll` 可覆盖电脑地址、没有 V3、主循环阻塞录像/语音/HTTP，旧板自动补传；完整 V3 应退出旧调度。
- 原两端只用 `ftyp` 和 100000 字节阈值判完整；短片结果与容器完整性应分开。
- 原 C 接收回执查询失败会自动上传；V3 查询未知先暂缓，肯定未保存才考虑许可重传。
- 原 Flutter 接收 A 会无条件清 device `holdOnline`；V3 仅清 A，不影响正在录 B。

## 必查矩阵

| 输入或故障 | 要求 | 验证方式 |
|---|---|---|
| 错来源/设备/nonce/boot/旧序号 | 不修改状态；查询回声对应请求 | 真 C 主机程序 UDP + 真 Flutter 控制客户端；另记录实板 TODO |
| enable A、disable、高序旧renew | 不复活 A；需新的enable/新gate | 真协调器定向测试及UDP黑盒 |
| 相同序号重发不同内容 | 不执行新动作；同事务仅返回既有结果 | 控制黑盒 |
| pair_commit ACK丢失、PC重启 | 通过持久pair事务+hello恢复已配对；不重播 | 两端真实持久状态重启测试 |
| 离线中右解除 | 立即撤旧控制、留event，Wi-Fi和视频保留 | 主机输入模拟 + 实板接线与Wi-Fi验证 |
| 开机按住/三键/采样间断/GPIO读失败 | 未重新全部松开不得开录；只在合法阶段配对 | 使用同一真实button入口的输入轨迹 |
| 开始语音期间松任一键/stop到达 | 不开录；已有录制stop不强停本段 | 真协调器 + 真录像RPC适配测试 |
| A完成、B准备、A迟到upload/status | B学生/许可/活动ID不变 | 真server与真session测试 |
| duplicate event或PC重启 | 仅一次推进；返回持久receipt | 重开真实session；不可只验证内存 |
| 完成保存失败后重试 | 未落盘不得ACK；内存回滚后可重试 | 真实session存储故障注入 |
| short/failed | 保原结果及学生；新capture_id重拍 | 真session及server测试 |
| 完成通知在hash未算时 | 提前报告；pending_query不阻塞loop | 真程序查询时延及worker日志 |
| grant A、录像B、upload A完成 | 只删A明确文件；不能清B或其事件 | 真pending文件与真协调器检查 |
| receipt超时/错hash/错size | 保文件；未知不盲重传；匹配才删 | 真C上传worker+真server回执；故障代理可只操作报文 |
| stop/失联/重启 | 当前已录段收尾；禁止下一段；重新点开始 | 真状态机 + 实板 |
| 60秒/低空间/低内存 | 正确拒录或安全收尾 | 真指标入口，实板真实资源测量 |

## 证据边界

两个各自 mock 实现之间能交流不能称跨端验收。主机 C + Flutter 原生接收服务可证明报文和持久状态互通，但无法证明 GPIO 电气条件、RKiPC 实际 MP4 收尾、喇叭时序、板端 PSS 或连续 20 轮指标。最终报告要分别标注源码审查、主机测试、交叉编译与实板。

## 本轮独立结果

执行 `v3_runtime_blackbox_review.py`，从真实 WSL 源码用 GCC `-Wall -Wextra -Werror` 构建隔离主机程序，使用真 `runtime_v3.c` 和真 LwBTN。33 项通过，完整列表在同目录 `V3真实C主机黑盒_2026-10-01.json`。

覆盖：开机许可关闭、窗口外拒配对、同一输入入口 3 秒开窗、配对提交及重复事务、提前 ID prepare、stop、乱序旧 enable、关闭和过期后旧 renew 不复活、错 boot 拒绝、control_sequence 供电脑重启恢复、板端进程重启换 boot 并保配对、原 txn 恢复确认、电脑源地址 127.0.0.1 切换为 127.0.0.2 后先拒控制再经同 txn 更新地址、旧 gate stop 不关闭新 gate、解除事件重启持久及确认清除。

测试隔离根 `/tmp/v3-independent-k3m9ff0p`，UDP 37021；未部署板，不调用 RKiPC，Wi-Fi/音频在显式主机测试模式跳过。不把主机 33 项结果宣称为完整跨端或实板验收。

审查中发现并由两端负责人修复：上位机写盘失败回滚、停止优先队列与序号恢复、配对丢 ACK 重启恢复、stop/new gate 取消范围、重复完成下一轮/姓名去重；固件维护任务饥饿、Wi-Fi 失败计数、迟到 recording ACK 误确认新轮、starting 松键通知、未开录失败时间戳；两端短片和回执规则。完成时间戳采用实际开录时刻加单调时钟录制时长，不含容器收尾时间。

最终源码复核已看到上位机持久 `committedPairTransactions`，板端 hello 含 `peer_ip/http_port`，两端可用原事务重确认地址；上位机解除时清除 pending/committed 配对事务，防止自动恢复重新认领。

最新只读复核已看到：固件开录不再等待 hash 维护或音频队列清空，录像 worker 串行处理待播语音并播放开始提示；上位机已保存记录时间采用 `actualStarts`，准备时间仅作回退。两端负责人报告已重新构建；独立 33 项黑盒的版本早于最终语音调度调整，最终实板录像收尾、20 轮与资源实测由主线程另存证据。
