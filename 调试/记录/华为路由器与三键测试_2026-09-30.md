# 华为路由器与三键实测

## 网络

- SSID：`MinMax-test`；路由器 `192.168.101.1`；板子 `192.168.101.3/24`；电脑以太网 `192.168.101.2/24`。密码不写入测试记录。
- WPA2-PSK / CCMP，2.4 GHz、2437 MHz，实测 RSSI 约 -22 dBm。
- 切换时重新获取 DHCP，旧 `192.168.0.66/23` 更新为新地址。通过后已 `save_config` 保存默认：新网络 priority=100、旧网络 disabled=1；同步 `/etc/wpa_supplicant.conf`，应用 `wifi_ssid=MinMax-test`。旧配置均有 `before-minmax-20260930` 备份。
- 板子 → 网关 10/10；电脑 → 板子 4/4；板子 → 电脑 4/4，均 0% 丢包。
- UDP 37020 按现有 V2 DISCOVER/HERE 协议连续 25 轮，每秒一轮，25/25 收到相应 nonce 的回复。
- 经 Wi-Fi ADB 推送并回读 8,388,608 字节：6.168 秒/6.206 秒，均约 1.3 MB/s；两份文件逐字节一致，SHA-256 `7d212b9c884f5c77896de960ae17cc341cda43b14d6a971f34ca29ebd4badf7f`。这是 Wi-Fi 二进制传输验证，不等同于正式 HTTP 录像上传。
- 电脑已有 Release 上位机占用 8080，现有 `board_e2e_test.dart` 因端口冲突未执行；没有关闭正在使用的应用。
- 初始摄像头未接，导致传感器识别失败。用户断电接好后 `m00_b_mia1321 4-0060` 正常识别，RKIPC 自动启动。
- RTSP-over-TCP 按现有预览参数分别连续测试 60、120、60 秒均结束成功，未发生原热点的断流故障。RTP marker 探针报告约 12.7 fps；这是探针计数值，未据此修改当前 `60/6`、640 kb/s 配置。
- 第一次正式录像生成在 `/userdata/video0`，而当前应用 `VIDEO_DIR=/video0`，导致查找失败。备份 `/userdata/rkipc.ini.before-router-20260930` 后，将 `storage.mount_path` 改为 `/`，`num_limit_enable=0`；保留旧录像，存储与应用根分区容量对应。
- 修复后 `flutter test tool/router_board_e2e_test.dart --reporter expanded` 三轮全通过，独立 8081 接收，测试后恢复 8080。T001/T002/T003 文件分别为 4,888,342 / 4,867,798 / 4,855,696 字节；板端三条 `upload acknowledged`，pending 和 `/video0` 为空。
- 三个 MP4 均 1280×1080、约 10 秒，完整解码 295 / 294 / 293 帧；文件帧率约 29.45 / 29.4 / 29.3，存在相对目标 30 fps 的少量偏差。哈希/文件路径见 `路由器三轮视频验证_2026-09-30.json`。
- 默认配置写入后实板重启：自动接入 MinMax-test，DHCP `192.168.101.3`、网关 `192.168.101.1`；RKIPC/仪器程序各一个进程；新存储配置保留，三键初始化日志全部为 1。
- 重启后两接收端同时运行复测：第一段进入 8081 测试端，第二段被 8080 正式上位机接收并确认，测试端超时。日志显示 DISCOVER 反复覆盖 `pc_base_url`；网络、录像及传输没有断开，但存在多上位机竞争目标的问题。本次不改生产协议，后续按 Wi-Fi/配对计划的电脑身份与地址校验处理；测试时暂时挂起正式上位机并在 finally 中恢复。
- 暂时挂起正式上位机后，重启后三轮隔离测试 `All tests passed!`，55 秒结束；finally 恢复正式接收端，`NtResumeProcess` 返回 0。三段大小 2,364,477 / 4,851,798 / 2,966,982 字节，完整解码 294 / 293 / 294 帧、均 10 秒；见 `重启后三轮视频验证_2026-09-30.json`。合计重启前后三轮各一次，六段隔离验收均成功。

## 三键

用户确认引脚：

| 位置 | 引脚 | GPIO 编号 | 初始电平 | 内核初始偏置 |
| --- | --- | --- | --- | --- |
| 左 | GPIO0_A3 | 3 | 1 | 上拉 |
| 中 | GPIO0_A4 | 4 | 0 | 下拉 |
| 右 | GPIO0_A0 | 0 | 0 | 无偏置 |

- debugfs 确认三路原先未占用；已导出并设为 `in`。未执行示例 `gpio.c` 的输出翻转。
- 用户确认低电平有效。起初 A4 下拉、A0 无偏置导致接地按键无法稳定区别松开/按下。
- GPIO character-device 请求输入上拉返回成功，但 pinconf/寄存器读回仍未改变；该临时 C 工具已撤下，不能把返回成功当配置生效。
- 按 Luckfox 官方驱动确认 PMUIOC `0xff388000`、GPIO0 pull offset `0x38`、每脚两位，1=上拉。仅写 A0/A4：`devmem 0xff388038 32 0x03030101`；原值 `0x268`、读回 `0x169`。其他引脚的位保持不变；A3 原本上拉。
- `调试/工具/button_inputs.sh` 对配置做精确读回检查，再设三路为输入；重复执行通过。`--restore` 可从 `/tmp/button-input-pull-before.txt` 恢复 A0/A4 偏置。初始原值另保留在电脑 `GPIO0上拉寄存器_改前_2026-09-30.txt`。
- 用户确认“目前的代码三个按键都能正常识别”；三路均观察到各自 1→0→1，松开为 1、按下为 0。
- `调试/工具/button_monitor.py` 同时显示左/中/右“按下/松开”和原始电平，PC 本地页面 `http://127.0.0.1:8766`，约 250 ms 刷新；断连显示未知。变化日志 `三键电平_2026-09-30.jsonl`。这是采样监视，不用于消抖/组合键时序验收。
- 板端 `/opt/instrument/bin/button_inputs.sh` 由 `/oem/usr/etc/init.d/S79buttons` 在 S80instrument 前执行；重启后三路输入上拉有效。回滚时停用这个单独启动入口，再恢复 A0/A4 原偏置即可，无需改主程序。
