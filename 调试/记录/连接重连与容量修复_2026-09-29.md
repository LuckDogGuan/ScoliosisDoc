# 连接重连与容量修复（2026-09-29）

## 实板定位

```text
电脑 Flutter 8080 ──UDP DISCOVER──> 板子 37020
       <────────── HERE ──────────┘
       <────────── HTTP hello ────┘
配对 / 解除事件由 hello 返回，板子回传 event-ack。
```

- ADB 下曾出现 `wpa_cli` 显示 `COMPLETED` 且保有 IP，但板子对电脑和网关的 ARP 都失败、ping 不通；手动 `wpa_cli disconnect`、`reconnect` 后恢复。这是独立于配对逻辑的链路故障，不能只凭 Wi-Fi 状态判断网络可用。
- 解除配对后，电脑端“历史设备”的“重新配对”只在最近 15 秒收到 HTTP hello 时可按；板子配置里的旧 USB 地址 `169.254.*` 无法让它主动报到，形成重连卡点。
- 板上原有 `/oem/usr/etc/init.d/S80instrument` 和 `/RkLunch.sh` 尾部各启动一次 `instrument_app`。实测两个进程、一次广播回两个 `HERE`。
- 关闭 Flutter 窗口后，应用进程和 8080 监听会退出；VS Code 的 Dart/Flutter 调试会话仍可能显示“运行”，因为 `flutter_tools.snapshot run --machine` / debug adapter 尚未结束。需要在 VS Code 按 Shift+F5 停止调试会话。
- eMMC 原始容量约 8 GB；`/` 分区约 5.8 GiB、可用约 5.4 GiB，`/userdata` 分区仅约 238 MiB。录像保存在 `/opt/instrument/capture` 所在根分区，而容量函数误查 `/userdata`，所以显示约 200 MB。

## 修复

- Flutter：历史设备离线时仍可提交重新配对；离线配对后主动广播发现。应用服务启动后主动发现，离线时每 10 秒重试；窗口关闭时取消重试任务。只有收到 HTTP hello 才显示在线、允许拍摄。音量弹窗拆到独立文件，保留设备页原有导出入口。
- 板端：`S80instrument` 统一从 `/opt/instrument` 启动；`/RkLunch.sh` 去掉重复启动行。程序目录与状态目录均保留 `/opt/instrument`。
- C 程序：每 10 秒检测默认网关 ARP；连续 3 次失败（包括 wlan0 失去 IP）后调用 `wpa_cli` 断开并重新连接，同时重置报到目标。电脑端重发 UDP 发现后恢复 HTTP hello。
- C 程序：`storage_free_mb()`、`storage_total_mb()` 改查 `PENDING_DIR` 所在文件系统；录像容量门槛与上报值因此对应真实保存位置。

## 验证与回滚

- ADB 重启后仅有一个 `/opt/instrument/bin/instrument_app`，UDP 37020 仅监听一次，一次广播仅回一个 `HERE`。
- C 交叉编译、`make -B check-host` 通过；实板一次性 HTTP hello 上报 `storage_free_mb=5504`、`storage_total_mb=5946` MiB。
- Flutter 定向测试、静态检查、Windows Release 构建通过。独立数据目录启动的 Release 监听 8080，并收到板子 HTTP 连接。实板配对→解除→再配对→解除事件均收到确认。
- ADB 主动 `wpa_cli -i wlan0 disconnect` 后直接运行 `flutter test tool/board_repair_test.dart -r expanded`，约 41 秒通过；`/var/log/messages` 记录网关 ARP 连续失败后的自动重连，以及随后选中电脑 `192.168.0.20:8080`。这条测试同时覆盖板端恢复、电脑端重试发现和二次配对。
- 板上旧文件分别保存在 `/RkLunch.sh.bak_20260929`、`/oem/usr/etc/init.d/S80instrument.bak_20260929`、`/opt/instrument/bin/instrument_app.bak_20260929`；`instrument_app.bak_gateway_20260929` 和 `instrument_app.bak_gateway_v1_20260929` 是中间版本。可逐个复制回原路径并重启。最终交叉编译产物与板上 `/opt/instrument/bin/instrument_app` 的 SHA-256 一致。
- 已验证一次强制断网恢复和多次配对往返；长时间、多路由器环境下的稳定性仍需现场观察。
