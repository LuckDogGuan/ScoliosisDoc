# 设备 IP 发现与 SSH 登录记录

验证时间：2026-10-02 15:41:55–15:41:58（Asia/Shanghai）。

结论：已通过真实 SSH 密码认证并在设备执行只读命令，不只是 TCP 端口探测。

## 官方依据

[Luckfox Pico Zero 官方登录文档](https://wiki.luckfox.com/zh/Luckfox-Pico-Zero/Login/)（2026-10-02 查阅）：Buildroot 登录名 root；默认口令见该页面。官方 USB 默认地址 172.32.0.93 不等于现场 Wi-Fi 地址。本次发现并使用 192.168.101.3。

## 执行过程

1. 读取 Flutter `data/设备.json`，取得已有设备 CAM-000123 和电脑身份，不修改配对记录。
2. 通过现有 Python Bridge 的临时本机 `/debug/udp` 服务，在电脑 192.168.101.2 和 192.168.0.20 网卡发送 UDP 37020 状态查询。192.168.101.2 接收到 CAM-000123 的合法 `hello_reply`，来源为 192.168.101.3:37020；另一网卡没有回复。
3. ADB 序列号 3253c006806f5194 的只读 `ip -4 addr show` 另行确认 wlan0 为 192.168.101.3/24，usb0 为 172.32.0.93/16。ADB `netstat -lnt` 显示 0.0.0.0:22 正在监听，没有启动或修改设备服务。
4. 使用本机 Python 3.12 / Paramiko 5.0.0，以 root 向发现地址的 TCP 22 认证。密码经标准输入传递，不写入证据文件。
5. SSH 执行 `id`、`hostname`、`uname -a`、系统与网卡查询、序列号查询，收到真实设备输出后关闭连接。

入口命令（交互密码）：

```powershell
Set-Location D:/code/Scoliosis/Luckfox
python 调试/工具/Python中间层/discover_ssh.py --bind 192.168.101.2 --bind 192.168.0.20 --ssh
```

实际自动运行使用同一命令附加 `--password-stdin`；不保存含口令的调用文本。
