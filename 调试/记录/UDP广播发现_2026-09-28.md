# UDP 广播发现：2026-09-28 实测

正常使用要靠局域网 UDP 广播让仪器找到电脑，再向这台电脑发 HTTP 报到。不能把电脑地址写死，也不能把连接改到 USB 网卡上。USB 只用于 adb 传程序和查状态。

这次程序已经装到板上，广播测试没有打通。下面按时间记实际发生的事，以及接下来要解决什么。

## 想做成什么样

1. 电脑在局域网网卡上广播 `DISCOVER`。
2. 仪器收到后，向发来的地址单播 `HERE`（设备号、固件版本、原样带回 nonce）。
3. 仪器把随后的 hello、取命令、上传，改发到这个广播来源的 IP 和端口。
4. 广播只表示“被发现”，不能代替配对，也不能授权上传视频。

报文约定（两边都已按这个写）：

| 方向 | 内容 |
| --- | --- |
| 电脑 → 仪器 UDP `37020` | `{"version":2,"op":"discover","nonce":"...","http_port":8080}` |
| 仪器 → 电脑来源端口 | `{"version":2,"op":"here","nonce":"...","device_id":"CAM-000123","firmware":"0.0.1"}` |

nonce 只含字母和数字，长度 4–64。`http_port` 必须在 1–65535。仪器监听 `0.0.0.0:37020`。

代码位置：

| 端 | 路径 |
| --- | --- |
| 下位机发现 | `src/net/discover.c`，主循环里调用 |
| 上位机发现 | `lib/net/udp_discover.dart`，设备页「刷新设备」会在每张局域网网卡上发 |

## 改之前

- 仪器配置里写死 `pc_base_url=http://192.168.0.20:8080`，大约每 3 秒主动 hello。
- 电脑 IP 一变，或 hello 到不了，上位机就只能显示旧的「上次报到」，没有主动发现。
- 2026-09-28 中午，上位机设备页上 CAM-000123 显示上次报到约 1 小时前，信号和剩余空间都是空的。当时电脑上没有进程在听 `8080`。

| --- | --- |
| 电脑 WLAN | `192.168.0.20/23`，`ChinaNet-7HrK`，BSSID `80:3c:20:5a:4e:38` |
| 仪器 wlan0 | `192.168.0.66/23`，同一 SSID、同一 BSSID，网关 `192.168.1.1`，无线 MAC `54:01:4a:4c:03:fb` |
| 仪器 usb0 | `172.32.0.93/16`。电脑上对应的 Remote NDIS 网卡当时是 `169.254.104.0/16` |

## 中途做过、但不能当正常方案的事

为了确认「是不是 Wi-Fi 根本不通」，在仪器 `usb0` 上临时加过 `169.254.104.50/16`。之后仪器 ping 电脑的 `169.254.104.0` 成功（2 次都通，约 2–11 ms）。

这条路说明 USB 线本身能传数据。它不是产品连接方式：要手改地址，电脑这个 `169.254` 地址重启后还可能变。用户已明确否定。开机脚本里对应的 `ip addr add` 已从 `调试/配置/方案/S80instrument` 去掉，并推回板子。不要再把 `pc_base_url` 改成 USB 地址。

## 改之后实际测到的

1. 交叉编译通过。本机 adb（`调试/工具/adb.ps1`，不要经 WSL 调 adb）把 `instrument_app` 推到 `/userdata/instrument/bin/instrument_app`。`--version` 为 `0.0.1`。
2. 进程起来后，`netstat` 能看到 `udp 0.0.0.0:37020`。当时进程号 2505。
3. 在电脑上把套接字绑到 `192.168.0.20`，发送发现包到 `255.255.255.255:37020`、`192.168.1.255:37020`，以及单播 `192.168.0.66:37020`。等了数秒，**电脑没有收到任何 HERE**。
4. 电脑到 `192.168.0.66` 的路由是 WLAN 上的 `192.168.0.0/23` 直连，没有绕进 Mihomo 或虚拟网卡。
5. 仪器上 `192.168.0.20` 的邻居项一直是 `INCOMPLETE`（ARP 探测失败）。网关 `192.168.1.1` 也是 `FAILED`。
6. 电脑侧曾显示 `192.168.0.66` 为 Reachable，MAC 与仪器无线地址一致，但两边 ping 都是 100% 丢失。可达表项不能当成数据已经互通。
7. 连续发出约 90 个 UDP 后，仪器 UDP 的 `InDatagrams` 没有增加，`192.168.0.20` 仍是 `INCOMPLETE`。这些发现包没有进入仪器的 UDP 协议栈。
8. 更早一次：电脑临时监听 `8080`，仪器 `wget http://192.168.0.20:8080/` 立刻失败，错误是 `No route to host`。8 秒内没有任何连接进来。

## 结论

发现程序在仪器上已经在听 `37020`，电脑也发出了广播和单播。失败点不在报文格式，而在 **这两台无线设备之间的帧到不了对方**。同一 Wi-Fi 下，ARP 完不成，ping 不通，UDP 也进不了仪器。常见原因是路由器打开了无线客户端隔离（AP 隔离）：客户端之间的单播和广播都被丢掉。

所以现在不能说「刷新设备就能发现仪器」。在网络放行之前，重复改上位机或下位机的发现代码，解决不了这次失败。

## 要解决的事

1. 让电脑和仪器在同一局域网里真正互通。二选一即可：
   - 关掉这台路由器上的无线客户端隔离 / AP 隔离；或
   - 电脑用网线接到这台路由器（很多路由器只隔离无线对无线，有线到无线仍然通）。
2. 互通之后再测，不要先改 USB 地址。通过标准：
   - 电脑发 UDP `DISCOVER` 后，能收到 `HERE`，里面是 `CAM-000123` 和 `0.0.1`；
   - 仪器日志出现 `UDP discover selected http://<电脑IP>:8080`；
   - 上位机 `8080` 在听，数秒内 hello 到达，设备页从「上次报到很久以前」变成刚报到，并带上信号、剩余空间和下位机版本。
3. 广播仍然不能代替配对。收到 `HERE` 之后，拍摄和上传还是走现有 HTTP，并且只有配对过的当前设备能开拍。
